Запусти программу из корня проекта:
    javac --release 17 -encoding UTF-8 -d out "@sources.txt"
    java -cp out Main --demo

Минута 1: демонстрация
Покажи T1-T7 и SUMMARY: 7/7 PASS. PASS получается из сравнения фактической
строки с ожидаемой, а не печатается заранее. Метод printCheck возвращает 1 при
успехе и 0 при ошибке; runDemo складывает эти значения. Если проверка ошибается,
программа показывает expected и продолжает остальные проверки.

Минута 2: роли и делегирование
Shape - Abstraction. Circle и Square - A1/A2. Renderer - Implementor.
VectorRenderer, RasterRenderer и AsciiRenderer - I1/I2/I3. Main - Client.
Две оси: какая фигура и каким способом её рисовать. Связь - поле
private Renderer implementation в Shape; оно получает объект через конструктор.
Пример вызова:
Main создаёт Circle с VectorRenderer -> Circle.execute() -> getImplementation()
-> VectorRenderer.renderCircle(radius) -> строка VECTOR circle radius=2.
В Circle нет new VectorRenderer(), проверки типа или приведения типа.

Минута 3: переключение
Circle original создаёт один объект. Circle switched = original копирует ссылку,
а не создаёт второй объект. original == switched проверяет именно идентичность
объекта; equals для строк проверяет содержимое ID и результатов.
setImplementation(new RasterRenderer()) меняет только поле implementation.
ID и radius остаются прежними: они private final. Первый execute использует
VectorRenderer, второй - RasterRenderer. Renderer-объект меняется, Circle - тот же.

Минута 4: расширение и Adapter
Покажи extension.diff. В src изменены только Main.java и добавлен
AsciiRenderer.java. Новая реализация соблюдает существующий интерфейс Renderer.
Shape, Circle, Square, Renderer и первые два renderer не менялись.
Bridge нужен для независимого изменения двух сторон. Adapter нужен, чтобы
приспособить уже существующий несовместимый API к ожидаемому интерфейсу.
В этом проекте все renderer изначально поддерживают одинаковый интерфейс.

Минута 5: методы и изменение входных данных
Circle.execute(): входных аргументов нет, используется сохранённый radius;
получает текущий renderer, вызывает renderCircle и возвращает результат.
setImplementation(Renderer): принимает ссылку на объект Renderer и сохраняет её.
checkResult: принимает ID проверки, подпись классов, Shape и ожидаемую строку;
запускает execute, сравнивает строки и отдаёт данные printCheck.
checkRuntimeSwitch: сохраняет состояние, запускает execute, меняет renderer,
запускает execute ещё раз и проверяет идентичность, состояние и обе строки.
Тернарный оператор condition ? a : b выбирает a при true и b при false.

Примеры, которые нужно уметь предсказать:
1. Circle с radius=5 и AsciiRenderer вернёт ASCII circle radius=5.
2. Square с side=7 и VectorRenderer вернёт VECTOR square side=7.
3. Если только входной radius в T1 поменять на 5, но оставить expected с 2,
   T1 получит FAIL: фактическая строка будет VECTOR circle radius=5.
4. Если в T5 оставить VectorRenderer вместо RasterRenderer, после переключения
   будет VECTOR circle radius=2; T5 станет FAIL, даже при sameObject=true.
5. Если только T6 переключить на VectorRenderer без изменения expected,
   получится VECTOR circle radius=2 вместо ASCII circle radius=2: T6 станет FAIL.
6. Новая фигура Triangle потребует новую операцию в интерфейсе Renderer и её
   реализацию в каждом renderer. Новый renderer для Circle/Square требует только
   новый класс с двумя существующими методами. Это конкретный компромисс дизайна.

Программа намеренно использует корректные фиксированные данные. В ней нет
проверки null или отрицательных размеров; эти дополнительные требования в задании
не заданы. При null renderer вызов execute приведёт к NullPointerException.

Разбери каждый метод и попробуй самостоятельно предсказать результат небольшого
изменения перед запуском: преподаватель может выбрать любую часть кода.
